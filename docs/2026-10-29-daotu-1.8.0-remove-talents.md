# 道途附属 v1.8.0 — 移除天赋（词条）

> 2026-10-29

## 一句话

道途**不再自带词条**。v1.4.0 从「天命」并进来的 72 条词条（以及驱动它们的一整套战斗/回复乘区）
全部删除，词条回归天命（K 键）独有。

---

## 一、为什么删

v1.4.0 把天命的 72 条词条抄了一份独立副本进道途的候选池，作为「一次性大礼」混在属性候选里。
两个问题：

1. **同一份内容维护两遍**：天命的词条改了，道途这份副本不会跟着变，迟早不一致；
2. **数值口径错配**：天命的词条是按「开局一次买断」设计的（例如「极·万世不灭」生命 +150%），
   放进道途「每局可重复抽」的池子里，后期属性会被推得过高。

现在职责切开：**天命管开局你是谁（体质 + 词条 + 机缘），道途管后来你成了谁（属性 + 特殊奖励）。**

---

## 二、删了什么

### 删除的源文件（3 个）

| 文件 | 原职责 |
|---|---|
| `DaotuTalent.java` | 72 条词条的数据表（id / 品质 / 成本 / 效果） |
| `DaotuTalentApply.java` | 把词条效果落到玩家身上、挑候选、记已获 |
| `DaotuCombatEffects.java` | 词条驱动的战斗/回复乘区（暴击 / 闪避 / 减伤 / 吸血 / 反伤 / 每秒回复） |

### 改动的源文件（6 个）

| 文件 | 改动 |
|---|---|
| `DaotuDrawTable.java` | 删 `TALENT_PREFIX`、`Candidate.isTalent()/talentId()`、词条候选生成 |
| `DaotuDraw.java` | `apply()` 去掉词条分支；`labelOf()` 去掉词条名解析 |
| `DaotuRun.java` | 删 `talents()` / `addTalent()`（`run/talents` 不再读写） |
| `DaotuEvents.java` | 拆掉 `DaotuCombatEffects` 的三处接线（受伤 / 伤害前 / 伤害后） |
| `DaotuRuntime.java` | 删每秒 `tickRegen` 调用 |
| `DaotuSpecial.java` | 删只被词条消费的 `DAOHEN_KEYS`；更新注释 |

### 顺手修的一个显示问题

`DaotuViewScreen.attrLabel()` 的 `default` 分支直接返回裸 key，导致：

- 老存档里抽到词条的历史记录显示成 `talent:ji_wanshi_bumie`；
- **v1.5.0 起的特殊奖励历史**也显示成 `special:daohen:jiandao`（这个 bug 一直存在）。

现在补了 `special:` 与 `talent:` 两个前缀的翻译，历史记录显示成「剑道道痕」「旧词条（v1.8.0 已移除）」。

## 三、对存档的影响

| 项目 | 影响 |
|---|---|
| 已抽到词条给过的**一次性属性 / 道痕** | **保留**。当时已写进 `run/attrs` 与本体道痕字段，删除代码不会回收 |
| 词条带来的**战斗乘区**（`c_*` 键） | **失效**。乘区的唯一读取方已删除 |
| 词条带来的**每秒回复** | **失效**。同上 |
| 词条带来的**常驻 buff** | **继续维护**。`DaotuBuffs` 未删，老存档里 `run/buffs` 仍每秒兜底续期 |
| `run/talents` 旧数据 | 不读不写，留着不影响；转世时随 `run` 一起清掉 |
| `run/attrs` 里的 `c_*` 旧键 | 仍被 `DaotuRunAttributes` 跳过（否则每次 sync 刷「未知属性键」日志） |

> `DaotuBuffs` 保留是**刻意**的：删了会让老存档的常驻 buff 立刻消失，而 buff 不在本次
> 「战斗乘区」的删除范围里。新玩家不会再产生新的 buff。

- `audit_v140.py` 原来断言「词条池 ≥ 60 条」「jar 内含 3 个天赋类」——已反转为「必须不存在」。
