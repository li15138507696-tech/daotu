# 道途 1.8.2 优化记录

基线为用户指定的 `daotu-1.8.1.jar`，SHA-256 为 `B6649C59B5322E575DECE7594F7A7446AB0943E8C35118DB3C3B759E6AED5244`。
编译依赖为用户指定的本体 9.8，SHA-256 为 `50219570D6CCC77072DEDC885840475C827C0A8469061565A8E494F5F808E0D9`，Minecraft 1.21.1、Java 21；沿用原工程的 NeoForge 21.1.249 平台依赖。本次遵照用户先前约束，没有启动客户端或服务端。

## 修改

- 属性维护改为核对实时修正，只更新金额或运算方式变化的项、移除已经撤销的项、补回被本体或其他附属清掉的项。仍每 5 秒兜底、仍按当前存档读取，不缓存玩家状态；修正 ID 只创建一次，属性注册表仍在应用时读取。
- 抽选生成最多执行一次检查。原先首次生成候选并发送提醒后，循环会再次进入“已有候选”分支并立即发送一份相同状态；现在去掉这次重复发送。后续已有候选时的刷新和选完后的下一批候选保留，历练仍在真正选择时才扣除。
- 纪事保存校验 revision 时，直接读取实时存档头并保留 schema 校验，避免为校验版本号再次解析势力组合、功绩解锁和声望解锁三份列表。UUID 校验、冲突拒绝、深拷贝和独立存档根保留。
- 每秒维护只判定一次开窍状态，并移除 1.4.0 后永远没有加成来源的气运维护死分支，避免无效访问本体附件；保留每秒补回奖励 buff 的机制。

成长值、软上限、奖励表、抽选上限、试炼进度、存档格式和网络协议没有改变。本次不改死亡/转世注入点。

## 本地验证

修改前，先用指定本体 9.8 重编译原源码：47 个源码文件生成的 62 个类，与用户提供的 1.8.1 JAR 逐类字节完全相同。

优化前与优化后各通过 84 项本地替身检查，直接编译并执行生产代码中的属性维护、抽选过程和纪事仓储。检查覆盖属性金额/运算方式、撤销、外部移除后的恢复、其他模组修正保留、客户端不写入、候选稳定、非法选择拒绝、扣费与发奖一次性、未开窍门禁、每转上限、每十抽特殊奖励、revision 冲突、未来/负 schema 拒绝、克隆深拷贝和其他存档根不被修改。

固定负载中的操作数对比：

- 对 14 项未变化属性重复维护 10,000 次：1.8.1 添加修正 140,000 次、移除 140,000 次；1.8.2 两者均为 0。首次授予与真实变更仍正常执行。
- 已有纪事的 CAS 保存校验：额外解析列表从 3 份降为 0；实际保存仍按原流程构建并提交完整记录。
- 刚生成一批候选：立即发送从 2 份降为 1 份，真正选择前的历练和奖励均不变。

这些是本地替身中的行为和操作数检查，不是游戏内的 TPS、帧率或多人承载量测试。本次没有把旧版服务端启动证据当成新版运行验证。

最终 1.8.2 全量编译与包检查通过：47 个主源码、62 个类、2 个 mixin，测试类未进入发布包。两个 mixin、本体版本检测、网络包类与成长存档类保持原字节码。
